# agent-development

产品需求文档（PRD）的规范、模型与模板仓库。

本仓库只回答两个问题：**PRD 该长什么样**，以及**怎么从零写出一份**。

| [三层需求架构设计方案](./prd/三层需求架构_FE_FP_RP_设计方案.md) | 需求怎么拆：Feature 管产品结构，Function Point 管规模与估算，Rule Point 管详细规则 |

一句话记住模型：

```text
Feature（FE）        产品功能 —— 管产品结构
  └── Function Point（FP）   功能点 —— 唯一估算单位
        └── Rule Point（RP）  规则点 —— 唯一验收单位
```

## 写一份 PRD 的四步

### 第 0 步 · 建目录

```bash
mkdir -p [项目名]-prd
```

文件命名规则见规范 §1.3：`[类型]-[4位序号]-[项目名]-[module]-[submodule].md`，编号全仓库唯一递增。

### 第 1 步 · 产品概述（一个产品只写一份）

```bash
cp prd/tmp-prd-0000-产品概述模板.md  [项目名]-prd/prd-0001-[项目名]-product-overview.md
```

写清楚：产品目标、目标用户与痛点、竞品、价值主张、KPI、范围与范围外、术语表。

> ⚠️ 后续新增功能**不要**再复制这份模板建第二份概述。补充背景写进模块设计或功能细节的对应章节。

### 第 2 步 · 需求索引（ID 的权威来源）

```bash
cp prd/tmp-prd-0003-需求索引模板.md  [项目名]-prd/prd-0000-[项目名]-requirement-index.md
```

先在这里登记 `MOD-xx` / `MOD-xx-SUB-xx` / `fun-[module]-[submodule]-NNNN`，**再去写正文**。顺序反了必然重号。

### 第 3 步 · 模块设计（Feature 层）

```bash
cp prd/tmp-prd-0001-模块设计模板.md  [项目名]-prd/prd-0002-[项目名]-module-design.md
```

按模块写：功能概述、核心功能清单与优先级、前后端实现要点、模块间依赖。一个 `##` 章节 = 一个 Feature。

### 第 4 步 · 功能细节（FP / RP 层）

```bash
cp prd/tmp-prd-0002-功能细节模板.md  [项目名]-prd/prd-0003-[项目名]-function-details.md
```

这是估算和验收真正落地的地方：

- 每个模块先给一张 **Function Points 一览**（类型 / 复杂度 / 权重 / 估算 / 状态）
- 每个 FP 下列出它的 **Rule Points**，每条 RP 必须可判定"满足 / 不满足"
- 需要验证的 RP 展开 **Given / When / Then** 作为验收标准

## 模板与产出文件对照

| 模板 | 复制后的文件名 | 一个项目几份 |
|---|---|---|
| `tmp-prd-0003-需求索引模板.md` | `prd-0000-[项目名]-requirement-index.md` | 1 |
| `tmp-prd-0000-产品概述模板.md` | `prd-0001-[项目名]-product-overview.md` | 1 |
| `tmp-prd-0001-模块设计模板.md` | `prd-0002-[项目名]-module-design.md` | 1 或按模块拆多份 |
| `tmp-prd-0002-功能细节模板.md` | `prd-0003-[项目名]-function-details.md` | 按模块拆多份 |

> 模板序号（`tmp-prd-000X`）与产出文件序号（`prd-000X`）各自独立递增，不要求对应。

## 提交前自检

完整清单见规范 §9，最常踩的六条：

- [ ] 文件名符合 `[类型]-[4位序号]-[项目名]-[module]-[submodule].md`，编号全仓库唯一
- [ ] 文档头有「关联文档」，本次改动已加修订历史并升版本号（三段式 `1.0.0`）
- [ ] 所有链接是相对路径，**跨文档锚点带文件路径**（裸锚点会落在本文件内失效）
- [ ] 需求 ID 已在需求索引登记，`module` / `submodule` 段与目录名一致
- [ ] 用「验收标准」，不用「接受度标准」；用「功能细节」，不用「详细细节」
- [ ] 没有用户故事（Story）、没有独立的 Acceptance Criteria 层——两者都已废弃

## 约定速查

| 维度 | 取值 |
|---|---|
| 文档状态 | `Draft` / `Review` / `Approved` |
| 需求状态 | `TODO` / `IN_PROGRESS` / `DONE` / `SKIP` |
| 优先级 | `P0` 必需 / `P1` 重要 / `P2` 可选 |
| 文档版本号 | 三段式 `主.次.修订`，如 `1.0.0` |
| FP 复杂度 / 权重 | `XS=1` `S=2` `M=3` `L=5` `XL=8` `XXL=13` |
| RP 复杂度 | `Simple=1` `Normal=2` `Complex=3` |
| 项目进度 | 按已完成 **FP 权重占比**，不按 Task 条数 |
